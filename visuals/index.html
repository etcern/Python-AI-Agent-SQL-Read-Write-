Architecture

Click any block to see what it does. Everything runs on your machine.

👤 You (Browser) Type questions in plain English
You open http://localhost:8501 in any browser. That's your chat window. Type a question like you'd ask a colleague — no SQL needed.
▼
📄 Streamlit app.py — The chat interface
Streamlit is a Python library that creates web pages from Python code. It draws the chat bubbles, sidebar, and input box — the "screen" of the app. File: app.py
▼
🧠 Agent + LangChain agent.py — The brain that plans
The agent is a loop: send your question to the AI, check if it wants to use a tool, run that tool, send the result back, repeat until done. LangChain makes connecting AI to tools easy. File: agent.py
▼ ▼
🤖 Ollama + Qwen Local AI on your GPU
Ollama runs AI models locally. Qwen 2.5 Coder 14B has 14 billion parameters and lives in your GPU's 16 GB VRAM. It reads text and generates responses, including deciding which tools to call. Configured in: config.py
🔧 Tools tools.py — 4 database functions
Tools are Python functions the AI can call — its "hands." We have 4: list_tables, describe_table, sample_table, execute_sql. File: tools.py
▼
🗃 SQLite Database data/ecommerce.db — 108 KB
A SQLite database is just a file on disk — no server needed. Ours has 4 tables: products (97 rows), customers (100), orders (500), order_items (~1400). Generated by: setup_db.py

The 4 Tools

Without tools, the AI can only talk. With tools, it can act.

📋

list_tables

Shows all tables in the database. The AI calls this first to see what data exists.

Result: "customers, orders, order_items, products"
🔍

describe_table

Shows column names & types for a table so the AI knows what fields exist.

Result: "id (INTEGER) first_name (TEXT) email (TEXT)..."
📑

sample_table

Shows a few example rows. Helps the AI understand actual data formats and values.

Result: (1, 'James', 'Smith', 'james@...')
⚡

execute_sql

Runs any SQL query. The most powerful tool — the AI writes SQL from what it learned.

SELECT COUNT(*) FROM customers WHERE country='US';
💡
Every tool has a "reasoning" parameter. Before calling any tool, the AI must explain why — this forces it to think before acting and gives you a debug trail.

The Flow

What happens from the moment you type a question to when you see the answer.

1. You type a question

"Who is my best customer?"

st.chat_input("Ask a question about your data...")

2. Streamlit sends it to the Agent

app.py calls the ask() function with your question and the chat history.

response = ask(query=prompt, history=history, model=model)

3. Agent sends everything to the AI

The system prompt + tools list + chat history + your question all get sent to Ollama.

response = model.invoke(history) # history includes EVERYTHING

4. AI model runs on GPU

Qwen 2.5 Coder processes all the text on your GPU. It decides: "I should call list_tables first."

5. Tool executes

Agent sees the AI wants list_tables, runs it, gets back the table names.

tool_response = call_tool(tool_call) # runs the Python function history.append(tool_response) # adds result to history

6. Loop repeats (AI thinks again)

The tool result goes back to the AI. It calls more tools or gives a final answer. Steps 3–6 repeat until done.

7. Agent returns the final answer

When the AI responds with text and no tool call, the loop stops. That text is the answer.

if not tool_calls: # no more tools to call? return response.content # done! return the answer

8. You see the answer

Streamlit renders the response in a chat bubble: "Your best customer is Nicole Bond with 12 orders totaling $1,847.50"

Keyword Bridges

Every new word connected to something familiar. Hover the blue wordsThese are keywords with built-in explanations! anywhere on this page for instant definitions.

LLM (Large Language Model)

🎯 You already know: Autocomplete on your phone
An LLM is autocomplete on steroids — it predicts entire paragraphs from patterns learned across billions of pages. Qwen 2.5 Coder is the LLM we use.

Ollama

🎯 You already know: VLC plays videos locally
Ollama is like VLC but for AI models. Instead of streaming from the cloud, you download the model and run it on your own machine. Private, free, offline.

Agent

🎯 You already know: A new employee given instructions
An AI agent reads its manual (system prompt), has access to specific tools, and figures out the steps on its own. You tell it WHAT you need, not HOW.

Tool Calling

🎯 You already know: Asking your assistant to look something up
"Check my calendar" → assistant opens the calendar app. Tool calling is the same: the AI says "I need to run a query" and the system runs it.

System Prompt

🎯 You already know: A job description
The system prompt is the AI's job description: "you are a SQL analyst, respond in markdown." Change it, change the AI's entire behavior.

Context Window

🎯 You already know: A desk with limited space
The AI can only "see" a limited amount of text at once (~8,192 tokens ≈ 6,000 words). Like a desk — pile too many papers and the oldest fall off.

Temperature

🎯 You already know: "Strictly by the book" vs "get creative"
Temperature 0 = consistent, factual answers (best for SQL). Temperature 1 = creative, varied (good for brainstorming). We use 0.

Parameters (14B)

🎯 You already know: Brain cells
14 billion parameters = 14 billion tiny numbers storing everything the AI learned. More = smarter but needs more memory. Ours fits in 16 GB VRAM.

VRAM

🎯 You already know: RAM, but for your graphics card
Your GPU has 16 GB VRAM. The AI model must fit in VRAM to run on the GPU. Our 14B model takes ~9 GB, leaving 7 GB headroom.

LangChain

🎯 You already know: An adapter plug for electronics
LangChain plugs AI models into tools, databases, and APIs using a standard interface. It's the adapter between the AI brain and the database hands.

Tokens

🎯 You already know: Syllables in a word
AI reads "tokens," not words. Roughly 1 token ≈ ¾ of a word. "Hello world" = 2 tokens. 8,192 tokens ≈ 6,000 words.

RAG

🎯 You already know: Open-book exam vs closed-book
RAG = Retrieval Augmented Generation. Instead of answering from memory (closed-book), you give the AI relevant documents to read first (open-book).

Scaling & Training

From "tweak a sentence" to "train your own model" — ordered by effort.

1

Change the System Prompt

Edit one text block in agent.py. Change the AI's personality, output format, or target audience.

5 minutes
2

Add Few-Shot Examples

Put example Q&A pairs in the prompt so the AI learns your preferred style.

15 minutes
3

Swap the AI Model

Change one line in config.py. Try bigger models for better SQL, smaller for faster responses.

10 minutes
4

Connect Your Own Database

Point DB_PATH to any SQLite file. For PostgreSQL/MySQL, swap the cursor helper in tools.py.

30 minutes
5

Add New Tools

Give the AI new abilities: create charts, export CSV, send emails. Each tool is one Python function.

1–2 hours each
6

Add RAG (Document Search)

Let the AI search your PDFs and docs before answering. Uses ChromaDB + an embedding model via Ollama.

Half day
7

Fine-Tune a Model

Use Unsloth + LoRA to train the model on your own Q&A data. Teach it your schema and patterns.

1–2 days
8

Multi-Agent Production System

Multiple AI agents working together: SQL agent, chart agent, report agent. Add auth, logging, deploy.

Weeks
